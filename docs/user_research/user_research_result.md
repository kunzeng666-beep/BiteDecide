## 一、 核心调研数据统计与分析

### 1. 就餐纠结频率（对应 Q1：你平时多久会纠结一次“吃什么”？）

| 选项 | 样本数 (人) | 占比 (%) | 分布可视化 |
| :--- | :---: | :---: | :--- |
| **A. 几乎每天** | **9** | **64.29%** | `████████████████████` |
| **B. 每周 3~4 次** | **2** | **14.29%** | `████` |
| **C. 每周 1~2 次** | **2** | **14.29%** | `████` |
| **D. 基本不纠结** | **1** | **7.14%** | `██` |

* **数据结论**：
  * 高达 **78.57%（11/14）** 的受访者每周至少纠结 3 次以上，其中近三分之二（**64.29%**）处于**“几乎每天都纠结”**的状态。
  * 这证实了“不知道吃什么”在大学生日常中属于**高频刚需痛点**，因此 `BiteDecide` 的交互流程必须追求**“打开即用、零学习成本、快速决策”**。

### 2. 纠结的核心原因归因（对应 Q2：你纠结的最常见原因是？）

| 选项 | 样本数 (人) | 占比 (%) | 分布可视化 |
| :--- | :---: | :---: | :--- |
| **A. 没胃口啥也不想吃** | **7** | **50.00%** | `███████████████` |
| **B. 选择太多看花了眼** | **7** | **50.00%** | `███████████████` |
| **C. 与同伴意见分歧** | **0** | **0.00%** | `` |

* **数据结论与 HCI 洞察**：
  1. **两大核心痛点完全平分秋色（各占 50.00%）**：
     * **痛点一：感官倦怠（没胃口啥也不想吃，50%）**——用户此时缺乏食欲刺激，如果界面只展示冷冰冰的文字菜名，很难激发食欲。
     * **痛点二：选择过载（选择太多看花了眼，50%）**——印证了经典 HCI 理论中的 *Choice Overload*，当外卖平台或食堂窗口选项过多时，用户会陷入决策瘫痪。
  2. **个人独立决策是绝对主流（同伴分歧占 0%）**：说明大学生最需要帮助的场景是**个人日常就餐决策**，而非多人聚餐投票。

### 3. 决策交互方式偏好（对应 Q3：你最喜欢通过哪种方式帮你抉择？）

| 选项 | 样本数 (人) | 占比 (%) | 分布可视化 |
| :--- | :---: | :---: | :--- |
| **C. 在一批推荐的食物里做出选择** | **7** | **50.00%** | `███████████████` |
| **B. 结合情绪和天气智能分析** | **5** | **35.71%** | `███████████` |
| **A. 用大转盘随机决定** | **2** | **14.29%** | `████` |

* **单维与交叉分析（Q1 $\times$ Q3 关键发现）**：
  * **85.71%（12/14）的用户倾向于“智能分析 + 小范围精选挑选”（B + C）**，而完全盲目的“大转盘随机”仅占 **14.29%**。
  * **深度交叉洞察**：在 Q1 选了 **“几乎每天纠结”的 9 位重度用户**中，有 **6 人（66.7%）选了 C（在一批推荐的食物里做出选择）**，**3 人（33.3%）选了 B（结合情绪和天气智能分析）**，**0 人选择纯转盘随机**！
  * **心理学解释**：每天纠结吃什么的人，并非真的“随便吃啥都行”，他们潜意识里有隐性标准，因此抗拒把决定权完全交给盲目随机；他们真正渴望的是**系统先帮他们把几十种食物缩小到 3~4 个契合当下状态的精选选项，最后由自己享受“拍板二选一/三选一”的掌控感**。

### 4. 状态与食物品类偏好矩阵（对应 Q4：处于以下状态时，你最想吃哪类食物？）

> *注：问卷收集过程中对选项 C/D 进行了微调（将“盖饭”与“拉面、米线、粥”合并为温热饱腹主食类，将“蛋糕、奶茶”独立为甜品饮品类），下表为统一归类后的统计结果：*

| 食物品类 \ 生理与情绪状态 | 🔥 压力大时 | 🔋 很累时 | ❄️ 天冷时 | 🎉 想犒劳自己时 |
| :--- | :---: | :---: | :---: | :---: |
| **A. 火锅、麻辣烫**（热辣浓郁系） | **28.57%** (4) | 0.00% (0) | **78.57%** (11) | 28.57% (4) |
| **B. 炸鸡、汉堡**（酥脆高热量系） | 21.43% (3) | 7.14% (1) | 0.00% (0) | **35.71%** (5) |
| **C. 拉面、米线/盖饭、粥**（温热主食系） | **28.57%** (4) | **50.00%** (7) | 14.29% (2) | 7.14% (1) |
| **D. 蛋糕、奶茶**（甜品多巴胺系） | 7.14% (1) | 21.43% (3) | 0.00% (0) | 14.29% (2) |
| **E. 沙拉、水果**（清爽轻食系） | 7.14% (1) | 14.29% (2) | 0.00% (0) | 7.14% (1) |
| **F. 其他** | 7.14% (1) | 7.14% (1) | 7.14% (1) | 7.14% (1) |

* **四大人群状态规律总结**：
  1. **压力大时（痛觉与碳水双通道解压）**：**火锅/麻辣烫（28.57%）**、**温热碳水主食（28.57%）** 与 **炸鸡汉堡（21.43%）** 呈三足鼎立（合计 **78.57%**），验证了压力下人体渴望辣椒素刺激、酥脆咀嚼感与高碳水慰藉的饮食心理学规律。
  2. **很累时（低负担温暖治愈）**：数据出现戏剧性反转——选火锅/麻辣烫的人降为 **0%**，而 **50.00% 首选“拉面、盖饭、粥”**，另有 **21.43% 选择“蛋糕、奶茶”**。说明极度疲惫时，用户排斥进食繁琐的食物，偏好省力、温热易消化的主食或快速补充糖分的甜品。
  3. **天冷时（温度成为绝对强约束）**：**92.86%** 集中在热食，其中 **“火锅、麻辣烫”以 78.57% 形成压倒性优势**，无人选择炸鸡、甜品或冷食沙拉。说明气温是推荐算法中权重极高的过滤因子。
  4. **想犒劳自己时（高热量多巴胺放纵）**：**“炸鸡、汉堡”（35.71%）** 与 **“火锅、麻辣烫”（28.57%）** 居前两位，加上 **“蛋糕、奶茶”（14.29%）**，合计 **78.57%** 倾向于高热量“放纵餐”。

## 二、 调研结论对 `BiteDecide` 产品与工程设计的直接指导

基于上述真实用户数据，我们对原定产品设想进行以下 **4 项关键工程与交互修正**：

### 1. 重新定义模式二的交互闭环：「情绪/天气智能分析 $\rightarrow$ 精选批次卡片二选一」
* **依据**：Q3 中 B（情绪天气分析，35.71%）与 C（在一批推荐食物中选择，50.00%）合计占 **85.71%**，且 Q2 显示 50% 用户“选择太多看花眼”、50% 用户“没胃口”。
* **设计落地方案**：
  * 将 B 与 C 融合成一个连贯的黄金流程：先让用户通过 **1~2 步超轻松的情绪/状态/天气点选**，系统后台基于加权评分算法筛选出 **Top 3~4 个最契合的美食卡片（带诱人视觉展示，解决“没胃口”）**，让用户在这 3~4 个精选结果中凭直觉拍板（解决“选择太多看花眼”并保留掌控感）。

### 2. 优化模式一（3D 扭蛋机）：强化「排除反悔」与「趣味盲盒体验」
* **依据**：纯随机仅占 14.29%，重度纠结者对纯随机信任度低。
* **设计落地方案**：
  * 3D 扭蛋机不仅要提供解压的物理翻滚动画，还必须内置 **「🙅 没胃口，排除它并重抽」** 以及 **「前置快捷过滤标签（如：今天很累/天冷）」**，让随机抽取变得“可控且聪明”。

### 3. 建立基于真实调研数据的「推荐算法初始权重矩阵」
* **依据**：直接采用 Q4 的真实样本概率分布，作为模式二推荐引擎的基础加权参数（Scoring Matrix）：
  * `State = 压力大`：热辣浓郁系 `+0.29`、温热主食系 `+0.29`、酥脆油炸系 `+0.21`
  * `State = 很累`：温热主食系 `+0.50`、甜品奶茶系 `+0.21`、清爽轻食系 `+0.14`、热辣火锅系 `-0.20`（降权）
  * `State = 天冷`：热辣火锅/汤锅系 `+0.79`、温热主食/汤面系 `+0.14`、冷食沙拉系 `-0.50`（强降权）
  * `State = 犒劳自己`：酥脆高热量系 `+0.36`、热辣大餐系 `+0.29`、甜品奶茶系 `+0.14`

### 4. 附近餐厅卡片的 UI 信息层级规范
* **依据**：Q5 关注度排序为 `店铺评分 (57.14%)` > `人均价格 (28.57%)` > `距离多远 (14.29%)`。
* **设计落地方案**：
  * 餐厅推荐列表卡片采用紧凑清晰的信息布局，**第一视觉焦点突出展示「⭐ 店铺评分（如 4.8 分）」与「💰 人均价格（如 ￥22/人）」**，右侧辅以「📍 距离（如 450m）」，无需在门店列表堆砌大图，保持界面清爽高效。
